# 第 4 周 · 一键部署手册

> 项目：云购生活 · 企业级数据仓库与经营分析可视化系统
> 主题：可视化与部署（Superset 仪表板 / ECharts 大屏 / Streamlit 问答 / Docker Compose）
> 环境：Windows 11 + Docker Desktop（WSL2 后端），实测 8 核 / 16 GB

---

## 一、一句话部署

```bash
cp .env.example .env          # 填 1 个模型 Key，生成 SUPERSET_SECRET_KEY
docker compose up -d          # 7 个容器，首次约 6~10 分钟（含镜像拉取与建表）
docker compose ps             # 7 个服务全部 healthy 即就绪
```

启动完成后可直接访问：

| 入口 | 地址 | 说明 |
|---|---|---|
| Superset 仪表板 | http://localhost:8088 | admin / `.env` 里的 `SUPERSET_ADMIN_PASSWORD` |
| Streamlit 问答 | http://localhost:8501 | 自然语言提问 → SQL → 图表 |
| 数据 API | http://localhost:8000/api/dashboard.json | 大屏取数接口（CORS 已放开） |
| ECharts 大屏 | 浏览器打开 `dashboard/echarts/index.html` | 或访问 API 同源的静态页 |
| HiveServer2 UI | http://localhost:10002 | 查执行计划、看 Tez 会话 |
| ClickHouse HTTP | http://localhost:8123 | `default` / `.env` 里的 `CLICKHOUSE_PASSWORD` |

## 二、前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| Docker Desktop | ≥ 4.30，启用 WSL2 后端 | `docker version` |
| 内存 | ≥ 8 GB 可用（Hive + Tez 占 3~4 GB） | Docker Desktop → Settings → Resources |
| 磁盘 | ≥ 20 GB（镜像约 6 GB + 数据卷） | `docker system df` |
| 端口 | 3307、9083、10000、10002、8123、9000、8088、8501、8000 未被占用 | `netstat -ano \| findstr :8088` |

> **3307 而不是 3306**：本机已装 MySQL80 服务占用 3306，宿主机侧改用 3307 映射；容器内部仍是 3306，Hive 的 `jdbc:mysql://mysql:3306` 不受影响。

## 三、服务清单

| 服务 | 容器名 | 镜像 | 端口（宿主:容器） | 数据卷 | 作用 |
|---|---|---|---|---|---|
| mysql | ydsh-mysql | `mysql:8.0` | 3307:3306 | `mysql_data` | Hive Metastore 元数据库 + `superset` 元数据库 + 服务层 `ydsh_ads` |
| hive-metastore | ydsh-hive-metastore | `apache/hive:4.0.0` | 9083:9083 | `hive_warehouse` | 元数据服务，必须先于 HiveServer2 就绪 |
| hive-server | ydsh-hive-server | `apache/hive:4.0.0` | 10000、10002 | `hive_warehouse` | HiveServer2，四层数仓的查询入口 |
| clickhouse | ydsh-clickhouse | `clickhouse/clickhouse-server:24.8` | 8123、9000 | `clickhouse_data` | 加速层，承载 ADS 结果表的毫秒级查询 |
| superset | ydsh-superset | 自建 `ydsh/superset:4.1.1` | 8088:8088 | `superset_home` | BI 仪表板，3 个数据源 / 10 个数据集 / 8 张图 |
| app | ydsh-app | 自建 `ydsh/app:4.1` | 8501:8501 | — | Streamlit 对话式问答（NL2SQL 闭环） |
| api | ydsh-api | 同 `ydsh/app:4.1` | 8000:8000 | — | 大屏取数 API（标准库 HTTP，无额外依赖） |

依赖关系（`depends_on` + 健康检查）：

```
mysql(healthy) ──► hive-metastore ──► hive-server(healthy) ──┬──► superset
                        │                                     ├──► app
                        └────────── clickhouse(healthy) ──────┴──► api
```

`hive-metastore`、`hive-server`、`superset` 都配了 `healthcheck`，`hive-server` 的健康检查是
`beeline -e "SELECT 1"`——它要真正跑通一次查询才算健康，因为容器"在跑"和"能查"是两件事
（Tez 会话没起来时端口也是通的）。

## 四、环境变量

`.env` 不进仓库（`.gitignore` 已排除），仓库只留 `.env.example`。必填项只有两处：

| 变量 | 必填 | 生成方式 | 缺失后果 |
|---|---|---|---|
| `SUPERSET_SECRET_KEY` | 是 | `python -c "import base64,os;print(base64.b64encode(os.urandom(42)).decode())"` | **容器直接启动失败**（见 `superset_config.py` 里的显式校验，不退化成默认值） |
| `SUPERSET_ADMIN_PASSWORD` | 是 | 自定义，建议 ≥ 12 位含符号 | 退回默认 `admin`，等于公网可登录 |
| `CLICKHOUSE_PASSWORD` | 是 | 自定义 | ClickHouse 用空密码启动 |
| `MYSQL_ROOT_PASSWORD` | 是 | 自定义 | 元数据库裸奔 |
| `DEEPSEEK_API_KEY` 等 | 否 | 见《API 配置指南》 | 不填则 NL2SQL 走规则模式，不报错 |

密钥管理三条硬规则：

1. **代码里不出现任何 Key**，全部走 `os.environ` / `.env`；`python/llm_provider.py` 只存"变量名"，不存"值"。
2. **配置校验前置**：`SUPERSET_SECRET_KEY` 缺失时抛 `RuntimeError` 而不是用默认值——默认值等于把会话签名公开。
3. **提交前双查**：`git ls-files | grep -i env` 与 `git log -p --all -S "sk-"` 两道关，确认历史里也没有明文。

## 五、首次启动的数据初始化顺序

容器起来 ≠ 数据就绪。首次部署要按下面的顺序把数据灌进去（每条命令都能重复执行）：

```bash
# 1) ODS：建库建表 + 导入原始 CSV + 行数校验
bash scripts/import_ods.sh

# 2) 清洗层
bash scripts/run_sql.sh sql/clean/10_quality_assessment.sql
bash scripts/run_sql.sh sql/clean/11_clean_missing_value.sql
bash scripts/run_sql.sh sql/clean/12_clean_duplicate.sql
bash scripts/run_sql.sh sql/clean/20_enum_standardize.sql
bash scripts/run_sql.sh sql/clean/21_abnormal_format.sql
bash scripts/run_sql.sh sql/clean/22_split_merge_map.sql
bash scripts/run_sql.sh sql/clean/23_quality_compare.sql

# 3) DWD / DWS
bash scripts/run_sql.sh sql/dwd/30_create_dim_tables.sql
bash scripts/run_sql.sh sql/dwd/31_create_fact_order.sql
bash scripts/run_sql.sh sql/dwd/32_load_dwd.sql
bash scripts/run_sql.sh sql/dwd/33_load_dws.sql
bash scripts/run_sql.sh sql/dws/50_build_dws_multi.sql
bash scripts/run_sql.sh sql/dws/51_build_dws_user.sql

# 4) ADS（注意顺序：40_eda.sql 会建 ads_kpi_overview 等 5 张表，
#    61 依赖它，漏跑会报 ads_user_value does not exist）
bash scripts/run_sql.sh sql/dwd/40_eda.sql
bash scripts/run_sql.sh sql/ads/60_build_ads_kpi.sql
bash scripts/run_sql.sh sql/ads/61_build_ads_app.sql

# 5) 导出服务层数据（同时产出大屏需要的 JSON/JS/CSV）
docker exec ydsh-app python /app/python/export_dashboard_data.py

# 6) 灌入 MySQL 服务层与 ClickHouse 加速层
docker exec ydsh-app python /app/python/load_mysql.py
docker exec ydsh-app python /app/python/load_clickhouse.py

# 7) 生成 Superset 数据源/数据集/图表/仪表板（幂等，可重复执行）
docker exec ydsh-superset python /app/pythonpath/provision.py
```

> **Git Bash 用户必看**：在 MINGW/MSYS 下执行 `docker exec ... /tmp/x` 这类命令时，
> `/tmp/x` 会被自动转成 `D:/...`，报 `No FileSystem for scheme "C"`。
> 解决：`export MSYS2_ARG_CONV_EXCL='*'`（`scripts/run_sql.sh` 内部也继承该变量，所以在脚本外先导出一次即可）。

    from superset.models.core import Database

## 七、日常运维

```bash
docker compose ps                      # 看状态
docker compose logs -f hive-server      # 跟日志
docker compose restart superset         # 重启单个服务
docker compose stop                     # 停机（保留数据卷）
docker compose down                     # 删容器（保留数据卷）
docker compose down -v                  # 连数据卷一起删（清库，慎用）
```

改了 `superset/superset_config.py` 或 `app/requirements.txt` 之后必须重建镜像，
这两个文件是 `COPY` 进镜像的，不是挂载的：

```bash
docker compose build superset app && docker compose up -d superset app
```

而 `superset/provision.py` 是**只读挂载**的，改完直接重跑即可，不用重建。

## 八、故障排查（全部为本项目真实踩过的坑）

### 1. 容器重建后所有表报 `FileNotFoundException`

```
FileNotFoundException: ... /opt/hive/data/warehouse/ydsh_ads.db/ads_kpi_core does not exist
```

**原因**：数据卷挂在 `/user/hive/warehouse`，但 `hive-site.xml` 的
`hive.metastore.warehouse.dir` 与 Metastore 里登记的 `table LOCATION` 都是
`/opt/hive/data/warehouse`。容器重建后文件还在卷里，元数据却指向一个空的可写层。

**处置**：把卷挂载点改成 `hive_warehouse:/opt/hive/data/warehouse`，然后
`docker compose up -d --force-recreate hive-metastore hive-server`。

**坑中坑**：分区表要单独迁移——`ALTER TABLE ... SET LOCATION` 改不到分区路径，
366 个 `order_date=*` 分区得逐个 `ALTER TABLE dwd_order PARTITION (order_date='...') SET LOCATION`。

### 2. `hive-server` 反复重启，日志 `HiveServer2 running as process 7. Stop it first.`

容器重启后残留了 PID 文件，启动脚本以为实例已在运行，于是退出、被 `restart: unless-stopped` 拉起、再退出。
`docker compose rm -sf hive-server && docker compose up -d hive-server` 解决。

### 3. Superset 起来后所有图表报 `No module named 'MySQLdb'`

Superset 的 `MySQLEngineSpec` 有两处写死 `import MySQLdb`，即使 URI 写的是
`mysql+pymysql://` 也绕不过。装 `mysqlclient` 要现场编译（镜像里没有 gcc），
改在 `superset_config.py` 里加一行兼容层即可：

```python
import pymysql
pymysql.install_as_MySQLdb()
```

### 4. Superset worker 反复退出，报 `Unknown database 'superset'`

官方镜像默认 `CMD` 直接跑 `run-server.sh`，跳过了建库 / `db upgrade` / `create-admin`。
必须覆盖 `CMD` 走自己的 `bootstrap.sh`。

### 5. 建 Hive 数据源 422 `Database could not be created`

日志里真正的原因是没有 `SHOW CATALOGS` 语法——Superset 4.1 的 Hive engine spec 声明了
`supports_catalog=True`，建库前会探测 catalog，而 `apache/hive:4.0.0` 不认。
在 `superset_config.py` 里关掉：

```python
from superset.db_engine_specs.hive import HiveEngineSpec
HiveEngineSpec.supports_catalog = False
```

### 6. 仪表板点柱子没有联动

`FEATURE_FLAGS` 一旦在 `superset_config.py` 里**整体重写**，`config.py` 里的默认项就全丢了，
包括 `DASHBOARD_CROSS_FILTERS`。必须显式补回 `"DASHBOARD_CROSS_FILTERS": True`。

### 7. ClickHouse 客户端报 `Cannot execute query in readonly mode`

ClickHouse 的 HTTP 接口**用 GET 就是只读**，`INSERT` / `TRUNCATE` 必须走 POST（即使 body 为空）。

### 8. 容器内调模型报 `Client.__init__() got an unexpected keyword argument 'proxies'`

`openai==1.54.4` 与 `httpx==0.28` 不兼容，`requirements.txt` 里锁 `httpx==0.27.2` 即可。

## 九、生产化差距（诚实说明）

本地部署与生产部署之间还差这些，交付时按需补齐：

| 项 | 当前做法 | 生产建议 |
|---|---|---|
| 密钥 | `.env` 明文文件 | Docker secrets / K8s Secret / Vault |
| 传输 | 全 HTTP | 前置 Nginx + TLS，`SESSION_COOKIE_SECURE=True` |
| 元数据库 | MySQL 单实例 | 托管 RDS + 定期备份 |
| Hive 执行引擎 | Tez（本地模式，每次约 0.5 s 启动开销） | 常驻 Tez 会话池 / 换 Spark Thrift Server |
| Superset | 单进程 | Gunicorn 多 worker + Celery + Redis 缓存 |
| 资源限制 | 未设 | 每个服务配 `deploy.resources.limits` |
