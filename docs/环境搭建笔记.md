## 三、问题记录（重要交付内容）

> 每个问题都按「现象 → 排查过程 → 解决方案」记录，这是答辩加分项。

### 问题 1：Docker Desktop 装上后一直报「WSL needs updating」，无法启动引擎

| 项 | 内容 |
|---|---|
| **现象** | Docker Desktop 4.96.3 启动后弹窗 `WSL needs updating / Run wsl --update`，引擎始终不起来。执行 `wsl --version` 报错或只打印版权文本。 |
| **排查过程** | 1. `wsl --version` → 无版本号，说明是 Windows 内置旧版 WSL，不是 Store 版。<br>2. 检查 `C:\Program Files\WSL` → 目录不存在。<br>3. `Get-AppxPackage *WindowsSubsystemForLinux*` → 空，Store 版未安装。<br>4. `wsl --update` → Win10/旧版内置 WSL 只查内核更新，输出「无更新可用」。<br>5. 改用 `winget install --id 9P9TQF7MRM4R --source msstore` → 报 `0x80073d21`。<br>6. `Get-AppxDefaultVolume` → `PackageStorePath = D:\WindowsApps`、`IsSystemVolume = False`。 |
| **根本原因** | 两个问题叠加：① 系统只有内置旧版 WSL，Docker 4.96.3 必须用 Store 新版；② 「新应用默认安装位置」被设成了 D 盘，而 WSL 属于系统组件类应用，微软强制只允许装到系统盘 C，于是被 Store 拒绝（`0x80073D21` 的确切含义是 *This app must install to your system drive*）。 |
| **解决方案** | 1. 以管理员身份执行 `Set-AppxDefaultVolume -Volume "C:"`，把默认安装盘改回 C。<br>2. 确认 `(Get-AppxDefaultVolume).PackageStorePath` 回读为 `C:\Program Files\WindowsApps`。<br>3. 重新执行 `winget install --id 9P9TQF7MRM4R --source msstore --accept-package-agreements --accept-source-agreements`。<br>4. 验证 `wsl --version` → `WSL 版本 3.0.1.0 / 内核 6.18.40.1-1`。 |
| **注意事项** | `Set-AppxDefaultVolume` **非管理员执行会静默返回成功但值不变**（不抛异常），必须真提权。 |
| **后续预防** | 记录在团队文档：装 Store 应用前先确认默认安装盘是 C。 |

### 问题 2：Metastore 启动即退出，日志报 `ClassNotFoundException: com.mysql.cj.jdbc.Driver`

| 项 | 内容 |
|---|---|
| **现象** | `docker compose up -d` 后 mysql 正常 healthy，但 `ydsh-hive-metastore` 反复重启，最终 `dependency failed to start: container ydsh-hive-metastore is unhealthy`，hive-server 根本没启动。 |
| **排查过程** | 1. `docker logs ydsh-hive-metastore` → 末尾出现 `Failed to load driver` / `Underlying cause: java.lang.ClassNotFoundException : com.mysql.cj.jdbc.Driver` / `*** schemaTool failed ***` / `Schema initialization failed!`。<br>2. 关键信息：连接 URL 与用户名都正确，说明不是配置错，而是驱动类加载不到。<br>3. 结论：镜像是官方 `apache/hive:4.0.0`，其 `/opt/hive/lib` 下没有 MySQL JDBC 驱动 jar。 |
| **根本原因** | `apache/hive:4.0.0` 官方镜像未内置 MySQL 连接器（内置的是 PostgreSQL 驱动），但 compose 里 `DB_DRIVER: mysql` 要求用 MySQL 做元数据库，因此 `schematool -initSchema` 直接失败，容器退出。 |
| **解决方案** | 1. 下载 `mysql-connector-j-8.0.33.jar`（2,481,560 字节，校验 `PK\x03\x04` 有效签名），放到项目 `./lib/` 目录。<br>2. 在 compose 的 `hive-metastore` 与 `hive-server` 两个服务下都加一行卷挂载：<br>`- ./lib/mysql-connector-j-8.0.33.jar:/opt/hive/lib/mysql-connector-j-8.0.33.jar`<br>3. `docker compose up -d --force-recreate` 重建。<br>4. 验证：metastore 变 healthy，MySQL 中 `metastore` 库生成 **83 张**元数据表。 |
| **后续预防** | 驱动 jar 随仓库一起提供（`lib/` 目录），并在 compose 里写好注释说明为什么必须挂载，避免队友重装环境再踩一次。 |

### 问题 3：建表报 `file:/user/hive/warehouse/ydsh_ods.db/ods_user is not a directory or unable to create one`

| 项 | 内容 |
|---|---|
| **现象** | 执行 `01_create_ods_tables.sql` 时 SQL 语句编译失败，`Execution Error, return code 40000 from DDLTask. MetaException(...)`，而建库语句 00 却能成功。 |
| **排查过程** | 1. `docker exec ydsh-hive-server id` → `uid=1000(hive) gid=1000(hive)`，Hive 以非 root 用户运行。<br>2. `ls -ld /user/hive/warehouse` → `drwxr-xr-x root root`，属主是 **root**。<br>3. 在容器内试建目录 `mkdir /user/hive/warehouse/testperm` → `Permission denied`。<br>4. `docker inspect` 确认 `hive_warehouse` 命名卷挂载到 `/user/hive/warehouse`。 |
| **根本原因** | Docker 首次创建命名卷时，挂载点目录默认属主是 `root:root`（755），而 Hive 进程以 `hive`（uid 1000）身份运行，没有写权限，所以无法在 warehouse 下创建库目录。建库（CREATE DATABASE）只是写元数据不落盘，因此 00 能过、01 才报错。 |
| **解决方案** | 执行一次目录属主修正：<br>`docker exec -u root ydsh-hive-server chown -R hive:hive /user/hive/warehouse`<br>修正后 `ls -ld` 显示 `drwxr-xr-x hive hive`，复测 `mkdir` 成功，重跑建表脚本通过。 |
| **后续预防** | 该修正对命名卷是持久的，重启容器不会丢；但若执行过 `docker compose down -v`（删除数据卷），需重新执行一次。已写入本文档第六节自检清单。 |

### 问题 4：`run_sql.sh` 执行 SQL 报 `No FileSystem for scheme "C"`

| 项 | 内容 |
|---|---|
| **现象** | 在 Git Bash 中运行 `bash scripts/run_sql.sh sql/ods/00_init_database.sql`，beeline 报 `No FileSystem for scheme "C"`，SQL 完全没有执行。 |
| **排查过程** | 1. 脚本把 SQL 拷进容器 `/tmp/`，再用 `beeline -f "/tmp/xxx.sql"` 执行。<br>2. 直接 `docker exec` 手敲同样命令却正常。<br>3. 定位到参数被改写：Git Bash（MSYS2）会把以 `/` 开头的参数自动转换成 Windows 路径，`/tmp/00_init_database.sql` 变成 `C:/Program Files/Git/tmp/00_init_database.sql`。<br>4. Hive 收到 `C:/...`，把 `C:` 当成 Hadoop 文件系统协议名，于是报 `No FileSystem for scheme "C"`。 |
| **根本原因** | MSYS2 的 POSIX 路径自动转换机制与容器内 Linux 路径冲突 —— 这是 Git Bash 上跑 Docker 的经典陷阱，Windows 原生 PowerShell / CMD 不会出现。 |
| **解决方案** | 执行前关闭路径转换：<br>`export MSYS2_ARG_CONV_EXCL='*'`<br>再运行脚本即正常；建库输出正确列出 `default / ydsh_dwd / ydsh_ods` 三个库。 |
| **后续预防** | 已把这一行写进本文档所有 Git Bash 操作示例的开头；若改用 PowerShell 执行则不需要。 |

## 四、常见问题速查表

> 提前整理好，答辩老师问「遇到过什么问题」时可对照讲解。

| 报错 / 现象 | 根本原因 | 解决方案 |
|---|---|---|
| `WSL needs updating` / `wsl --version` 无版本号 | 只有内置旧版 WSL，Docker 4.96.3 要求 Store 版 | 装 Store 版 WSL（见问题 1） |
| winget 装 WSL 报 `0x80073d21` | 系统组件类应用强制装 C 盘，但默认安装盘不是 C | `Set-AppxDefaultVolume -Volume "C:"`（需管理员） |
| 容器启动后立即退出 | 依赖服务未就绪（MySQL 还没起来 Metastore 就启动） | 用 `depends_on: condition: service_healthy` 控制启动顺序；`docker logs <容器名>` 看具体报错 |
| `dependency failed to start: container ... is unhealthy` | 上游容器健康检查没过 | 先 `docker logs` 看上游容器，不要在报错的容器上找原因 |
| `ClassNotFoundException: com.mysql.cj.jdbc.Driver` | 官方 Hive 镜像未内置 MySQL 驱动 | 挂载 `mysql-connector-j-8.0.33.jar` 到 `/opt/hive/lib/`（见问题 2） |
| `is not a directory or unable to create one` | 命名卷挂载点属主是 root，Hive 以 hive 用户运行 | `docker exec -u root <容器> chown -R hive:hive /user/hive/warehouse`（见问题 3） |
| `No FileSystem for scheme "C"` | Git Bash 把 `/tmp/x.sql` 转成 `C:/Program Files/...` | `export MSYS2_ARG_CONV_EXCL='*'`（见问题 4） |
| `Connection refused` 连接 10000 端口 | HiveServer2 还在初始化 | 等 60~90 秒；`docker logs -f ydsh-hive-server` 观察；检查 `docker ps` 是否为 `Up` |
| 端口 10000 被占用 | 本机已装过 Hive 或其他服务 | `netstat -ano \| findstr 10000` 找到 PID 后结束进程，或改 compose 端口映射 |
| 端口 3306 被占用 | 本机已安装 MySQL 服务 | 改 compose 端口映射为 `3307:3306`，容器内仍是 3306 |
| Metastore 报 `Table 'metastore.VERSION' doesn't exist` | 元数据表未初始化 | 确认 `IS_RESUME: "false"`，让入口脚本跑 `schematool -initSchema` |
| `docker compose` 命令找不到 | 装的是旧版 Docker（只有 `docker-compose`） | 升级 Docker Desktop 到 4.x，或改用 `docker-compose up -d` |
| `docker pull` 超时 / `dial tcp ... timeout` | Docker Hub 在境内被 DNS 污染，解析到非法 IPv6 | 配 `registry-mirrors`（见下方 补充方案 C） |
| 导入后行数比预期多 1 | 表头未跳过 | 建表加 `TBLPROPERTIES('skip.header.line.count'='1')` |
| `No files matching path file /data/xxx.csv` | CSV 没放进 `data/` 或文件名大小写不一致 | 统一改为全小写 `.csv` |
| 字段串列 | CSV 用引号包裹且内含逗号 | 改用 OpenCSVSerde，见 `data/README.md` |
| `UPDATE` 语句报 `ParseException` | Hive 不支持行级 UPDATE | 改用 `INSERT OVERWRITE TABLE ... SELECT ...` |

## 五、补充方案

### A. Hive 起不来的排查顺序

按依赖链从下往上查，不要跳步：

```bash
# 1. MySQL 是否健康
docker exec -it ydsh-mysql mysqladmin ping -uroot -proot

# 2. Metastore 是否起来
docker logs ydsh-hive-metastore | tail -50
# 期望看到：Started Hive Metastore

# 3. Metastore 端口是否通
docker exec -it ydsh-hive-metastore bash -c '</dev/tcp/127.0.0.1/9083' && echo OK

# 4. HiveServer2 是否起来
docker logs ydsh-hive-server | tail -50

# 5. warehouse 目录属主是否正确（问题 3 的复查）
docker exec ydsh-hive-server ls -ld /user/hive/warehouse

# 6. 全量重启（保留数据卷）
docker compose restart
```

### B. 如果 Metastore 报 MySQL 驱动缺失

`apache/hive:4.0.0` 官方镜像未内置 MySQL 驱动。两种解法：

**解法 1：手动挂载 MySQL 驱动（本项目采用，已验证可行）**

把 `mysql-connector-j-8.0.33.jar` 放到 `./lib/`，在 `hive-metastore` 与 `hive-server` 两个服务下都加：

```yaml
    volumes:
      - ./lib/mysql-connector-j-8.0.33.jar:/opt/hive/lib/mysql-connector-j-8.0.33.jar
```

**解法 2：改用 PostgreSQL 做元数据库**

```yaml
  postgres:
    image: postgres:15
    environment:
      POSTGRES_USER: hive
      POSTGRES_PASSWORD: hive
      POSTGRES_DB: metastore
    ports: ["5432:5432"]
```

把 metastore 的 `SERVICE_OPTS` 换成：

```
-Djavax.jdo.option.ConnectionDriverName=org.postgresql.Driver
-Djavax.jdo.option.ConnectionURL=jdbc:postgresql://postgres:5432/metastore
-Djavax.jdo.option.ConnectionUserName=hive
-Djavax.jdo.option.ConnectionPassword=hive
```

> 注意：这属于环境层替换，不影响课程交付内容；在笔记里如实记录偏差原因即可。

### C. Docker Hub 拉不动时配镜像加速

现象：`docker pull` 报 `failed to resolve reference ... registry-1.docker.io ... dial tcp [2a03:2880:...]:443: connectex: ...`。这是 Docker Hub 在境内被 DNS 污染。

编辑 `C:\Users\<用户名>\.docker\daemon.json`（保留原有内容，只加 `registry-mirrors`）：

```json
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io",
    "https://docker.1panel.live"
  ]
}
```

然后在 Docker Desktop 里点 **Apply & restart**（设置 → Docker Engine），或重启 Docker Desktop。

验证：

```bash
docker info --format '{{json .RegistryConfig.Mirrors}}'
# 输出：["https://docker.1ms.run/","https://docker.m.daocloud.io/","https://docker.1panel.live/"]
```

配好后 `docker pull mysql:8.0` 不再需要手动加镜像前缀。
