## 一、方法：先统计，后生成

很多「AI 洞察」的做法是：把数据丢给模型，让它说点什么。这样做的问题很明显——模型不知道哪条是异常，只能说些"整体平稳、需关注波动"的废话；更糟的情况是它编一个原因，而没人能验证。

本项目的顺序反过来：

```
统计检测异常 → 量化归因 → 生成文字
```

- **异常检测**用规则，不用模型：偏离前 7 日均值多少、z 值多少，全部可复算。
- **归因**用维度分解，不用模型：把偏差拆到渠道和品类，算出各维度的金额贡献。
- **文字**才是模型该干的活（已接入智谱 `glm-5.3-flash`，真实生成结果见 4.2；无 Key 时降级模板）。

这样即使模型不给力，结论依然成立；模型只影响表达，不影响判断。

## 二、异常检测

### 2.1 判定方法

以「当日 GMV 相对前 7 日均值的偏离度」为指标：

```
偏离度 = (当日 GMV − 前 7 日均值) / 前 7 日均值
z 值   = (当日 GMV − 前 7 日均值) / 前 7 日标准差
```

基线**不含当日**，否则异常值会污染自己的参照系。

### 2.2 阈值敏感度：一个必须先回答的问题

| 阈值 | 命中天数 | 占比 | 判断 |
|---|---|---|---|
| 偏离 25% | 78 天 | 21.3% | ❌ 太松，五分之一都叫异常，等于没有异常 |
| 偏离 35% | 25 天 | 6.8% | ⚠️ 偏松 |
| **偏离 40%** | **11 天** | **3.0%** | ✅ 合理 |
| 偏离 50% | 7 天 | 1.9% | ⚠️ 偏严，会漏掉真实异常 |
| z > 2 | 36 天 | 9.8% | ⚠️ 偏松 |
| z > 2.5 | 16 天 | 4.4% | ✅ 合理 |
| **z > 3** | **10 天** | **2.7%** | ✅ 合理 |

**关键观察**：两种完全不同的判据（偏离 40% 与 z>3）收敛到 **10–11 天**。两条独立路径给出同一个数量级，说明这个量级才是「真异常」，而不是阈值调出来的。

z 值分布：中位数 0.82、95 分位 2.43、最大 8.16。也就是说，绝大多数日子 z < 1，属于正常波动。

**本报告采用「偏离 40%」作为主判据**（可读性优于 z 值，业务方容易理解），z>3 作为交叉验证。

### 2.3 为什么不用 25% 阈值

初版脚本用的是 25%，跑出来 78 天异常。这个结果本身就是个信号：**当一个检测器把 21% 的样本判为异常时，异常的是检测器，不是数据。**

真实业务里日销波动 20% 很常见（受促销、天气、周末影响），25% 的阈值必然误报。最终改为 40%。

## 四、自动经营分析摘要

### 4.1 生成方式与分工

数字全部由脚本算好，模型只负责组织语言。这条界线不能模糊：一旦让模型自己算，它给出的增长率就没有任何可复算的来源。

当前环境已配置智谱 Key，脚本会真实调用模型撰写摘要（`glm-5.3-flash`），产出同时写入 `data/insight_result.json` 的 `narrative` 字段与 `data/insight_narrative.md`。无 Key 或调用失败时降级为模板，且**在输出里明确标注是降级**——不让降级结果冒充能力。

### 4.2 模型撰写的摘要（真实调用）

```
全年GMV达36,116,687.06元，成交14,398单，客单价2,508.45元。1,000名下单用户
人均下单14.40次，复购率100%，用户粘性表现突出。订单取消率14.05%，需持续关注；
整体折扣率11.77%，价格让利幅度相对温和，全年经营规模与用户活跃度均处于较好水平。

两天异常主要由CH04与CH01拉动。7月6日CH04增量最大，达38,231元，CH01为21,502元，
品类上运动户外24,247元最突出，家居生活11,428元次之；6月22日CH01与CH04增量接近，
分别为21,120元和19,304元，母婴玩具18,261元与服饰鞋包16,775元大体均衡，未出现
单一品类主导。

一是品类份额接近、缺乏主打，建议从占比靠前的品类中选出两三个集中选品与流量资源
做重点突破，观察份额能否拉开；二是用户人均下单14.40次，建议核查频次在1,000名
用户中的分布，对高频用户做会员留存激励，对低频用户做定向唤醒触达。
```

**数字核对**：逐个回查脚本传入的事实，全部一致（`38,230.94→38,231`、`24,246.77→24,247`、`21,120.38→21,120`、`18,260.90→18,261`）。模型没有编造任何一个数。

**但它有一处判断是错的**：把「复购率 100%」解读成「用户粘性表现突出」。这份数据里 1,000 个用户人人下单 14.4 次、单次购买用户占比 0%，这在真实业务里不可能出现，是模拟数据的生成痕迹，不是经营成果。模型只对「数字念得准不准」负责，不对「这个数字合不合理」负责——后者只能靠人（见 4.3）。

### 4.3 一个必须写下来的教训：思考长度会撑满预算

这次为了让模型写摘要，前后失败了五次，全部是同一个现象：`finish_reason=length`、`content` 为空、`reasoning_content` 长达几千到三万字。实测记录：

| 配置 | 思考段长度 | 正文 | 结果 |
|---|---|---|---|
| `max_tokens=1024` | 2,076 字 | 0 字 | 失败 |
| `max_tokens=2048` | 2,638 字 | 330 字 | 成功 |
| `max_tokens=8192` | 16,057 字 | 0 字 | 失败 |
| `max_tokens=16384` | 29,904 字 | 0 字 | 失败 |
| 不传 `thinking` 参数，`max_tokens=1024` | 1,434 字 | 114 字 | 成功 |
| `thinking.level=low`，`max_tokens=1024` | 2,798 字 | 0 字 | 失败 |
| `thinking.type=disabled` | — | — | 400：该模型始终思考，不支持关闭 |

两条结论，都和直觉相反：

1. **思考长度跟着 `max_tokens` 上限走**。给多少预算它就想掉多少，所以「加大预算」解决不了问题，只会让它想得更久。之前以为 `max_tokens=800` 不够是预算问题，其实调大只会恶化。
2. **`level=low` 并不「少想」**，同等预算下思考量反而比不传参数更多。项目原先在 `llm_provider.py` 里给智谱配了 `thinking.level=low`，这个配置本身就是错的，已删除。

最终解法是**把任务切小**：一次写 300-400 字它想不完，那就拆成「整体表现 / 异常日分析 / 建议」三段、每段 100 多字，分别调用再拼接。思考量随任务规模同步下降，三段都稳定返回。

> 这件事和第 2 周那个「阈值公式与文档声明不一致」是同一类：**看起来是模型不听话，实际是参数和任务形状不匹配**。如果只看到「模型返回空内容」就去换模型、加预算，会一直撞墙；把 `finish_reason` 和 `reasoning_content` 长度打出来，问题一眼就清楚了。

### 4.4 结构性结论（同一份数据的模板版）

以下结论由脚本统计得出，不依赖模型，模型只影响表达：

### 2024 年经营概览

- 全年 GMV **3,611.67 万元**，订单 **14,398 单**，客单价 **2,508.45 元**。
- 下单用户 **1,000 人**，人均下单 **14.40 次**，复购率 **100.00%**。
- 订单取消率 **14.05%**，整体折扣率 **11.77%**。
- 全年 366 天中，**11 天**出现显著异常波动（偏离前 7 日均值 40% 以上，占 3.0%）。

### 波动结构

- 异常以上涨为主：Top 3 异常日全部为大幅上涨（+60% ~ +75%）。
- 下跌侧最极端的一天是 2024-07-28，GMV 55,713.60 元，较基线低 53.0%，z = −8.16——这是全年最异常的一天，值得单独排查。
- 异常日的增量主要由渠道侧贡献（CH01 / CH04 反复出现），品类侧贡献分散。

### 需要关注的三件事

1. **2024-07-28 的暴跌没有任何解释**。z = −8.16 意味着偏离了近 8 个标准差，正常业务波动很难到这个程度。优先怀疑数据采集缺失（当天部分渠道数据未落库），而不是真实业务下滑。
2. **渠道集中度高**。CH01 与 CH04 在两个 Top 异常日里都是主要贡献者，说明 GMV 对这两个渠道的依赖较强，一旦渠道侧出问题，整体波动会被放大。
3. **品类结构过于均匀**。八个品类 GMV 占比 11.02%–14.95%，最大与最小只差 4 个百分点。真实零售不可能这样（通常头部品类占 30% 以上）。这提示数据可能是模拟生成的，所有品类相关结论都应打折看待。

## 五、这份洞察的局限

诚实地列出来，比藏着好：

1. **没有外部事件数据**。促销、节假日、竞品动作全都没有，"为什么涨"永远只能答到渠道/品类这一层。
2. **没有用户行为链路**。只有下单结果，看不到曝光、点击、加购，无法判断是"流量变多"还是"转化变好"。
3. **单年数据**。做不了同比，也就无法区分"异常"和"季节规律"。
4. **归因是相关不是因果**。渠道 CH01 贡献了 +21,502 元，不等于"CH01 导致了增长"——也可能是整体流量上涨，CH01 只是分到了更多。
5. **数据真实性存疑**（见《预测建模分析报告》第 6.4 节）。若数据是模拟的，所有"洞察"都只是对随机数的描述。

**结论**：这套方法可以复用到真实数据上，但现在这份数据得出的具体结论，不建议作为经营决策依据。

## 六、复现

```bash
python python/ai_insight.py
# 产出：
#   data/insight_result.json    结构化结论（含每个异常日的渠道/品类归因明细）
#   data/insight_narrative.md   模型撰写的摘要（无 Key 或失败时不生成，脚本打印降级原因）
```

可用环境变量调整，不必改代码：

```bash
AI_INSIGHT_MODEL=glm-4.5 python python/ai_insight.py       # 换写作模型
AI_INSIGHT_MAX_TOKENS=2048 python python/ai_insight.py     # 收紧预算
```

阈值可调：`detect_anomalies(daily, threshold=0.40)`。
