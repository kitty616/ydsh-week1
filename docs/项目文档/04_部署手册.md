## 一、一句话部署

```bash
cp .env.example .env      # 第一次：填 4 个必填口令
docker compose up -d      # 起 7 个服务
```

等约 90 秒（首次拉镜像会更久）后：

| 入口 | 地址 | 说明 |
|---|---|---|
| 智能问答 | http://localhost:8501 | Streamlit，自然语言问数 |
| BI 仪表板 | http://localhost:8088 | Superset，admin / 见 `.env` |
| 取数 API | http://localhost:8000/api/health | 大屏数据接口 |
| ClickHouse | http://localhost:8123 | HTTP 接口，需口令 |
| 数据大屏 | 直接打开 `dashboard/echarts/index.html` | 纯静态，双击即可 |

## 二、前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| Docker Engine | ≥ 24.0 | `docker version` |
| Docker Compose | v2（`docker compose` 而非 `docker-compose`） | `docker compose version` |
| 内存 | ≥ 8 GB 可用（Hive + Superset 都吃内存） | `docker info` 看 `Total Memory` |
| 磁盘 | ≥ 10 GB | — |
| 端口 | 3306 / 8123 / 8000 / 8088 / 8501 / 9000 / 10000 / 9083 未被占用 | `netstat -ano \| findstr :8088` |

**Windows 用户三条注意事项**：

1. 必须启用 WSL2 后端（Docker Desktop → Settings → General → Use WSL 2）；
2. **Git Bash 会做路径转换**：执行 `docker exec ... /tmp/x.sql` 时 `/tmp` 会被改写成
   `D:/...`。解决：命令前加 `export MSYS2_ARG_CONV_EXCL='*'`；
3. 仓库路径**不要含空格**，Hive 的 `LOAD DATA LOCAL` 对空格敏感。

## 三、服务清单

| 服务 | 容器名 | 端口 | 镜像 | 健康检查 |
|---|---|---|---|---|
| MySQL | `ydsh-mysql` | 3306 | `mysql:8.0` | `mysqladmin ping` |
| Hive Metastore | `ydsh-hive-metastore` | 9083 | `apache/hive:4.0.0` | TCP |
| HiveServer2 | `ydsh-hive-server` | 10000 | `apache/hive:4.0.0` | TCP |
| ClickHouse | `ydsh-clickhouse` | 8123 / 9000 | `clickhouse/clickhouse-server:24` | `SELECT 1` |
| Superset | `ydsh-superset` | 8088 | 自建（基于 `apache/superset:4.1.1`） | `/health` |
| 问答应用 | `ydsh-app` | 8501 | `ydsh/app:4.1`（自建） | TCP |
| 取数 API | `ydsh-api` | 8000 | 同上镜像，换入口 | TCP |

自建镜像是必需的：官方 `apache/superset:4.1.1` 里**没有** `pymysql`、`pyhive`、
`clickhouse-connect`，直接配数据源会全部失败。

## 四、环境变量

`.env` 从 `.env.example` 复制，**必填 4 项**，缺任意一项 `docker compose up` 会直接报错退出：

| 变量 | 必填 | 说明 | 生成方式 |
|---|---|---|---|
| `MYSQL_ROOT_PASSWORD` | 是 | MySQL root 口令，同时用于 Hive Metastore | `openssl rand -base64 18` |
| `CLICKHOUSE_PASSWORD` | 是 | ClickHouse default 用户口令 | 同上 |
| `SUPERSET_SECRET_KEY` | 是 | Superset 会话签名密钥，**必须 42 字节 base64** | `python -c "import base64,os;print(base64.b64encode(os.urandom(42)).decode())"` |
| `SUPERSET_ADMIN_PASSWORD` | 是 | Superset 管理员口令 | 自定，≥ 12 位含符号 |

可选（不填则 AI 问答降级为规则匹配，其余功能不受影响）：

| 变量 | 说明 |
|---|---|
| `ZHIPU_API_KEY` / `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` | 任意一家即可，优先级见《API 配置指南》 |
| `SUPERSET_ADMIN_USER` / `SUPERSET_ADMIN_EMAIL` | 默认 `admin` / `admin@ydsh.local` |

**为什么强制必填**：所有口令在 compose 里都写成 `${VAR:?请设置}`。
变量缺失时编排直接失败，而不是退化成一个写在仓库里的默认值——
**"能跑起来"比"安全"重要的项目，最后通常既不安全也跑不久。**

## 五、首次启动的数据初始化顺序

容器起来 ≠ 数据就绪。首次部署按下面顺序灌数据，**每条命令都可重复执行**：

```bash
# 0) 确认 7 个服务全部 healthy（不是 up，是 healthy）
docker compose ps

# 1) ODS：建库建表 + 导入 6 个 CSV + 行数校验
bash scripts/import_ods.sh

# 2) 清洗层：体检 → 五类清洗 → 前后对比
for f in sql/clean/1[0-2]_*.sql sql/clean/2[0-3]_*.sql; do
  bash scripts/run_sql.sh "$f"
done

# 3) DWD / DWS
for f in sql/dwd/3[0-3]_*.sql sql/dws/5[01]_*.sql; do
  bash scripts/run_sql.sh "$f"
done

# 4) ADS（顺序不能乱：40_eda.sql 先建 ads_kpi_overview 等 5 张表，
#    61 依赖它，漏跑会报 ads_user_value does not exist）
bash scripts/run_sql.sh sql/dwd/40_eda.sql
bash scripts/run_sql.sh sql/ads/60_build_ads_kpi.sql
bash scripts/run_sql.sh sql/ads/61_build_ads_app.sql

# 5) 导出服务层数据（同时产出大屏用的 JSON / JS / CSV）
docker exec ydsh-app python /app/python/export_dashboard_data.py

# 6) 灌入 MySQL 服务层与 ClickHouse 加速层
docker exec ydsh-app python /app/python/load_mysql.py
docker exec ydsh-app python /app/python/load_clickhouse.py

# 7) 生成 Superset 数据源 / 数据集 / 8 张图 / 仪表板（幂等，可重复执行）
docker exec ydsh-superset python /app/pythonpath/provision.py
```

> 大屏若直接从 `file://` 打开，浏览器会拦截 `fetch` 本地 JSON。
> `export_dashboard_data.py` 已同时产出 `dashboard.js`（内联快照），因此双击
> `dashboard/echarts/index.html` 即可正常展示，不依赖任何服务。

## 六、验收：一条命令验证全链路

```bash
docker cp python/verify_e2e.py ydsh-app:/app/verify_e2e.py
docker exec -w /app ydsh-app python verify_e2e.py
```

预期输出（约 30 秒）：

```
| PASS | 64 |
| FAIL | 0 |
| WARN | 3 |
**结论：端到端链路全绿**
```

67 条断言覆盖 ODS 行数、DWD 去重、DWS 四维度求和、ADS 指标自洽、预测指标、
NL2SQL 返回值、大屏接口、三引擎一致性、7 服务端口连通。

只看某一层时，可直接查：

```sql
SELECT COUNT(*) FROM ydsh_ods.ods_order;            -- 15,600
SELECT COUNT(*) FROM ydsh_dwd.dwd_order;            -- 14,398
SELECT ROUND(SUM(gmv),2) FROM ydsh_dws.dws_trade_day;   -- 36,116,687.06
SELECT * FROM ydsh_ads.ads_kpi_core;                -- 10 个核心指标
```

## 七、预测模型的复现（独立环境）

预测训练需要 `scikit-learn`（约 200 MB），**运行时镜像里不装**——为演示引入这么大的
依赖不划算，预测结果是离线产物。需要重训时：

```bash
.venv-analytics/bin/python python/ts_forecast.py               # 产出 data/forecast_7d.csv 与 forecast_metrics.json
```

## 八、常见问题

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | Hive 容器反复 `Restarting`，日志 `HiveServer2 running as process 7. Stop it first.` | 容器重启后残留 PID 文件，启动脚本死循环 | `docker compose rm -sf hive-server && docker compose up -d hive-server` |
| 2 | 所有 Hive 表报 `FileNotFoundException ... /opt/hive/data/warehouse/xxx does not exist` | 卷挂载点与 `hive.metastore.warehouse.dir` 不一致 | 卷必须挂 `/opt/hive/data/warehouse`；已登记的 `table LOCATION` 需一并 `ALTER TABLE ... SET LOCATION`，分区表还要逐个 `ALTER TABLE ... PARTITION` |
| 3 | `bash scripts/run_sql.sh` 报 `No FileSystem for scheme "C"` | Git Bash 把 `/tmp/x.sql` 转成了 `C:/...` | `export MSYS2_ARG_CONV_EXCL='*'` |
| 4 | ClickHouse 报 `Cannot execute query in readonly mode` | HTTP GET 被强制按只读执行 | `TRUNCATE` / `INSERT` 必须用 **POST**（`--data-binary`） |
| 5 | Superset 启动报 `No module named 'MySQLdb'` | Superset 硬编码 `import MySQLdb` | `superset_config.py` 里 `pymysql.install_as_MySQLdb()` |
| 6 | Superset worker 反复退出，日志 `Unknown database 'superset'` | 镜像默认 CMD 是 `run-server.sh`，跳过了建库 | `CMD ["/bin/bash","/app/bootstrap.sh"]`，先 bootstrap 再起服务 |
| 7 | 建 Hive 数据源报 422 `Database could not be created` | 4.1 会探测 `SHOW CATALOGS`，`apache/hive:4.0.0` 不支持 | `HiveEngineSpec.supports_catalog = False` |
| 8 | Superset 点柱子不联动过滤其他图 | 4.1 前端行为，配置项齐全但不生效 | 改用「月份」原生筛选器；已在文档中如实记录 |
| 9 | 应用容器报 `Access denied for user 'root'@... (using password: NO)` | `app` 服务漏注入 `MYSQL_ROOT_PASSWORD` | 已在 compose 补齐（第 5 周联调修复） |
| 10 | `AttributeError: module 'openai' has no attribute 'Client'` 或 `unexpected keyword 'proxies'` | `openai 1.54` 与 `httpx 0.28` 不兼容 | `requirements.txt` 锁 `httpx==0.27.2` |
| 11 | 大屏打开一片白 / 图表不出来 | `file://` 下 `fetch` 被 CORS 拦截 | 用 `dashboard.js` 内联快照；或起 `python -m http.server` 走 http |
| 12 | Superset 中文地图不着色 | `country_map` 的关联键写死 `feature.properties.ISO` | 维度列必须是 `CN-SN` 这种 ISO 3166-2 编码，传省名匹配不到 |

## 九、停止、清理与重置

```bash
docker compose stop            # 停止，保留数据
docker compose down            # 删除容器与网络，保留数据卷
docker compose down -v         # 连数据卷一起删（会清空数仓，需重新初始化）
docker compose logs -f superset   # 跟踪某个服务日志
```

**清空重来的正确姿势**：`down -v` 之后必须重跑第五节的 7 步初始化，
否则表结构在但文件不在，会报第 2 条那个 `FileNotFoundException`。
