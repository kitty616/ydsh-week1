## 一、本周任务详细化

本周从"把数据算准"进入"把结果讲清楚、把系统跑起来"：先用 Superset 把 ADS 层指标做成可交互的仪表板，
再用 ECharts 做一块能上投影的数据大屏，接着把第 3 周的 NL2SQL 内核嵌进 Streamlit 形成问答闭环，
最后用 Docker Compose 把 7 个服务编排成一键部署，并补上密钥管理、查询优化与压力测试。

### 子任务 1：Superset 连接数据源与仪表板（2 课时）

**任务目标**：连接 Hive 与 MySQL（额外接 ClickHouse），基于 ADS 层指标表定义数据集，制作 ≥5 个图表并组合成带筛选器的仪表板。

**操作步骤**：
① 自建镜像补驱动——官方 `apache/superset:4.1.1` 连 MySQL 驱动都没有，Hive 的 thrift 协议栈更不用说；
② 三个数据源由脚本幂等创建：Hive（`hive://hive@hive-server:10000/ydsh_ads`）、MySQL 服务层、ClickHouse 加速层；
③ 建 10 个数据集，覆盖 ADS 应用表与服务层结果表；
④ 8 张图覆盖任务书要求的五类：折线（销售趋势）、柱状（品类销售）、地图（区域分布）、饼图（支付方式占比）、TopN 排行表，另加两张环图；
⑤ 三行布局组成仪表板，配一个「月份」原生筛选器，作用域绑定两张月度图。

**关键决策**：图表配置走**容器内 ORM**（`superset/provision.py`），不走 REST API。
REST 版本连撞三堵墙：写接口要 CSRF（纯 Bearer → 400）、补 Cookie 后 GET 列表 422、
建 Hive 数据源时探测 `SHOW CATALOGS` 又 422。ORM 方案绕开整条认证链路，且幂等可重跑。

**产出物**：`superset/Dockerfile`、`superset/bootstrap.sh`、`superset/superset_config.py`、`superset/provision.py`、`docs/images/w4_superset.png`。

**验收标准**：图表丰富、联动正确、指标准确。
**实测**：3 个数据源 / 10 个数据集 / 8 张图 / 1 个仪表板（`/superset/dashboard/ydsh-week4-ops/`）；
① 折线 12 个月合计 = 36,116,687.06，与 Hive/ClickHouse/MySQL 三处全年 GMV 一致；
地图按 ISO 3166-2 关联，34 个省级单元中 15 个有数据、正确着色；
「月份」筛选器加载出 12 个选项，作用域绑定 ②③。
**未达成**：图表交叉筛选（点击柱子联动其它图）三项配置均已就位，但实测点击只弹 tooltip、未触发联动，
已作为已知问题记录在《可视化设计说明》2.3 节，不按"已验证"上报。

### 子任务 2：ECharts 复杂图表与数据大屏（2 课时）

**任务目标**：读后端 JSON 接口，实现折线/柱状/散点/热力/地图五类图表，完成自适应布局与整体视觉设计。

**操作步骤**：
① `python/export_dashboard_data.py` 作为**唯一取数出口**，查 9 类数据后同时产出 `dashboard.json`（给 API）、
`dashboard.js`（给 `file://` 直接打开）、`data/serving/*.csv`（给 MySQL/ClickHouse 灌数）；
② 七个面板：月度成交趋势（柱+折线双轴）、下单时段×品类热力、品类构成、区域分布 TOP12、
门店经营质量散点（GMV × 客单价，气泡=订单量）、支付方式占比、门店 GMV 排行；
③ 自适应用**固定 1920×1080 舞台 + `transform: scale()`**，不用 rem/vw——大屏版式是设计出来的，不是流出来的；
④ 数据加载双通道：优先 fetch API，失败回落 `window.DASHBOARD_DATA`，断网也能演示。

**关键返工**：热力图做了三版。第一版按明细金额算，整片颜色几乎一样——排查发现明细表 `unit_price`
是**标价**不是成交价，`SUM(quantity × unit_price)` 算出 6.17 亿，而订单实付 3,611 万，**差 17 倍**；
第二版改订单数，仍偏均匀；第三版改**行内归一化**（该品类该时段订单 ÷ 该品类全天订单），
规律立刻出来：生鲜集中在 17–19 点，图书文娱集中在 21–23 点。

**产出物**：`dashboard/echarts/index.html`、`dashboard/echarts/vendor/echarts.min.js`（本地化，不依赖 CDN）、
`python/export_dashboard_data.py`、`app/api_server.py`、`docs/images/w4_dashboard.png`。

**验收标准**：图表多样、自适应、视觉美观。
**实测**：7 个面板全部出图；1920×1080 舞台在 1366×768 / 1600×900 / 1920×1080 三种分辨率下等比缩放无错位；
断网（不起 API）双击打开 HTML 仍能完整渲染。

### 子任务 3：Streamlit 对话式问答界面（2 课时）

**任务目标**：接入第 3 周 NL2SQL 后端（查询 Hive），实现"提问 → 生成 SQL → 执行 → 图表渲染"闭环。

**操作步骤**：
① `app/hive_client.py` 做双模式访问层（`pyhive` 直连 / `beeline` 命令行），
把结构化结果拼成 nl2sql 期望的 `(rows, err)` 形状——**第 3 周内核一行都不用改**；
② `app/app.py` 复用 `nl2sql.ask()`，新增 `ask_with_repair()`：把数据库报错喂回模型让它改一次；
③ ECharts 用 `st.components.v1.html` 内联渲染，图表库走本地 vendor，不依赖 CDN；
④ 侧边栏显示运行状态（Hive 连通性实测耗时、大模型是否配置），示例问题一键填充，
回答里 `大模型 / 执行 0.0s / 返回 12 行 / 已自修复 1 次` 全部摊开，SQL 收在可展开折叠块。

**关键修复**：模型给 `ads_monthly_trend` 写了 `WHERE year = '2024'`，但该表只有 `month`（形如 `2024-06`），
Hive 报 `SemanticException [Error 10004]`。这类错误**静态校验拦不住**（语法合法、只是列不存在），
所以做了两层：Prompt 加第 11 条硬约束 + 执行期报错回灌自修复一次。

**产出物**：`app/app.py`、`app/hive_client.py`、`app/Dockerfile`、`app/requirements.txt`、`docs/images/w4_streamlit.png`。

**验收标准**：闭环完整、交互友好。
**实测**：容器内提问「2024 年每个月的 GMV 趋势」→ 大模型生成 SQL → 执行 0.0s → 返回 12 行
（含 `month / gmv / mom_rate`）→ 结果表 + 图表双 Tab，界面标注"已自修复 1 次"；
6 月 GMV 2,829,996.31 与手工核算一致。

### 子任务 4：Docker Compose 一键部署（2 课时）

**任务目标**：编排 Hive（Metastore）、MySQL、ClickHouse、Superset、Python App 等服务，处理依赖与健康检查，密钥走环境变量。

**操作步骤**：
① 7 个服务：`mysql` / `hive-metastore` / `hive-server` / `clickhouse` / `superset` / `app` / `api`；
② 依赖用 `depends_on` + `healthcheck` 双保险，`hive-server` 的健康检查是真正跑一次 `beeline -e "SELECT 1"`——
容器"在跑"和"能查"是两件事；
③ 密钥全部走环境变量：`SUPERSET_SECRET_KEY` 缺失时**容器直接启动失败**，不退化成默认值；
④ 数据卷 4 个（`mysql_data` / `hive_warehouse` / `clickhouse_data` / `superset_home`），
`hive_warehouse` 挂载点必须与 `hive-site.xml` 的 `warehouse.dir` 一致，否则容器重建后元数据与文件错位。

**产出物**：`docker-compose.yml`、`.env.example`、`.dockerignore`、`docs/第4周_部署手册.md`。

**验收标准**：编排规范、一键启动、密钥安全。
**实测**：`docker compose up -d` 后 7 个容器全部 healthy；Hive/ClickHouse/MySQL 三处日表 GMV 均为 36,116,687.06；
`git ls-files` 与 `git log -p -S "sk-"` 双查无明文密钥。

### 子任务 5：密钥安全、查询优化与压力测试（2 课时）

**任务目标**：规范密钥管理，优化核心 Hive 查询（分区裁剪、倾斜、分桶），做并发压测并写手册。

**操作步骤**：
① 密钥三原则：代码里不出现 Key（只出现变量名）、配置校验前置、提交前双查；
② `python/bench_query.py` 做四个实验：E1 分区裁剪、E2 小表 Join、E3 三引擎对比、E4 并发压测；
③ 判据从"看秒表"改成"看执行计划"——用 `EXPLAIN DEPENDENCY` 数 `input_partitions`；
④ 写《部署手册》与《API 配置指南》。

**产出物**：`python/bench_query.py`、`data/bench/bench_result.json`、`docs/第4周_压力测试记录.md`、
`docs/第4周_压测原始输出.md`、`docs/第4周_部署手册.md`、`docs/第4周_API配置指南.md`。

**验收标准**：查询优化到位、压测记录完整。
**实测**：
- 分区裁剪：命中分区 366 → 1；函数包裹分区键时 `input_partitions` 变空（等于扫全表）；
- 小表 Join：普通 JOIN 与 `/*+ MAPJOIN */` 执行计划**都是 Map Join**（Hive 4 自动转换），耗时差 +1.0% 属抖动；
- 三引擎：ClickHouse 比 Hive 快 **118~170 倍**，MySQL 单次最快（0.3 ms）；
- 并发：Hive 4 并发 QPS 4.17、P95 1247.7 ms；ClickHouse 8 并发 QPS **924.83**、P95 10.7 ms；MySQL 8 并发 QPS 728.08。

## 三、本周踩坑清单（按发现顺序）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 容器重建后所有 ADS 表 `FileNotFoundException` | 卷挂 `/user/hive/warehouse`，元数据指向 `/opt/hive/data/warehouse` | 改挂载点，并逐个迁移 366 个分区 LOCATION |
| 2 | `hive-server` 反复重启，日志 `HiveServer2 running as process 7` | 残留 PID 文件 | `docker compose rm -sf` 后重建 |
| 3 | 图表全报 `No module named 'MySQLdb'` | Superset 硬编码 `import MySQLdb` | `pymysql.install_as_MySQLdb()` |
| 4 | Superset worker 反复退出 `Unknown database 'superset'` | 官方镜像 CMD 跳过建库步骤 | 覆盖 `CMD` 走 `bootstrap.sh` |
| 5 | 建 Hive 数据源 422 | 4.1 探测 `SHOW CATALOGS`，Hive 4.0.0 不认 | `HiveEngineSpec.supports_catalog = False` |
| 6 | 点柱子无联动 | `FEATURE_FLAGS` 整体覆盖丢了 `DASHBOARD_CROSS_FILTERS` | 显式补回（但仍未验证通过，见上文） |
| 7 | ClickHouse `Cannot execute query in readonly mode` | HTTP 用 GET 就是只读 | `INSERT`/`TRUNCATE` 走 POST |
| 8 | 容器内调模型 `unexpected keyword argument 'proxies'` | `openai 1.54.4` 与 `httpx 0.28` 不兼容 | 锁 `httpx==0.27.2` |
| 9 | 热力图整片同色 | 明细 `unit_price` 是标价，比实付大 17 倍 | 改订单数口径 → 再改为行内归一化 |
| 10 | 地图边界画出但不着色 | 关联键写死 `properties.ISO` | entity 改传 ISO 3166-2 码 |
| 11 | `docker exec ... /tmp/x` 报 `No FileSystem for scheme "C"` | Git Bash 把 `/tmp` 转成 `D:/` | `export MSYS2_ARG_CONV_EXCL='*'` |
| 12 | 压测 E1 判据反了（包函数反而"更省"） | 用了 CBO 的过滤后行数，不是读取行数 | 改用 `EXPLAIN DEPENDENCY` 数分区 |
